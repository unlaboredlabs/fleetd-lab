fleetd's merge train is the only thing that merges pull requests into main in this repository. When a task branch such as fleetd/T1-write-alpha-md is ready, fleetd spawns tier reviews of the change, rebases the branch onto main, and waits for the ci check to pass. Only then does the train squash-merge the pull request and post the fleetd/train commit status that main's branch protection requires, so contributors never merge or post that status by hand. If the rebase hits a conflict or CI goes red, the train returns the branch to the writer rather than merging it. CI fails whenever a file named FAIL exists at the repository root, as the README describes.
