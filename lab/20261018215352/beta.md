fleetd's merge train is the only path that merges task pull requests into main in this repository. When a task branch is ready, the train runs tier reviews on the pull request, rebases the branch onto the current main, and waits for the required CI check to report green before it merges, using squash merges only. Writers never merge their own pull requests or post the fleetd/train commit status, since that status is how the train marks its own merges. If the rebase hits a conflict or CI turns red, the train does not merge, and the pull request goes back to the writer to fix and push again.
