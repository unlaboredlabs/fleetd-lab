fleetd's merge train is meant to be the only thing that merges pull requests in this testbed. The README says `main` should require the `ci` check and the `fleetd/train` commit status, and allow squash merges only; the repo settings do allow only squash merges, and the `ci` workflow fails whenever a file named `FAIL` exists at the repo root. However, `main` currently has no branch protection (the protection endpoint returns 404), so nothing enforces the required checks today, and a pull request can be merged without the train. Until protection is configured, the train's gate is a convention rather than a rule.
