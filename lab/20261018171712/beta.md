fleetd's merge train takes a writer's pull request and lands it on main without anyone merging it by hand. It rebases the branch onto the current main, gets the change through the tier reviews that its risk level requires, waits for the required ci check to pass, and then merges it. If the rebase hits a conflict, a review asks for changes, or ci comes back red, the train does not merge; it sends the problem back to the writer so the branch can be fixed and requeued. The train is the only actor that posts the fleetd/train commit status that main requires, so a writer never merges or marks the pull request as passing on its own.
