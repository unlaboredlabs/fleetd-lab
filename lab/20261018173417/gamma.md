fleetd's merge train is meant to be the only thing that merges pull requests in this testbed. The README says `main` should require the `ci` check and the `fleetd/train` commit status, and allow squash merges only; the repo settings allow only squash merges, and the `ci` workflow fails whenever a file named `FAIL` exists at the repo root. However, `main` has no branch protection enforcing those checks, so a pull request can be merged without the train. Until protection is configured, the train's gate is a convention rather than a rule.
