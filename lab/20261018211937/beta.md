fleetd's merge train is the component that lands pull requests on `main`, so writers never merge their own work. Once a pull request has passed the tier reviews its risk level requires, the train rebases it onto the current `main`, waits for the required `ci` check to pass, and then merges it. If the rebase conflicts, a review asks for changes, or `ci` fails, the train leaves the pull request unmerged and sends the problem back to the writer so the branch can be fixed and requeued. The train is also the only actor that posts the `fleetd/train` commit status that `main` requires, which is why a pull request cannot land until the train has set it.
