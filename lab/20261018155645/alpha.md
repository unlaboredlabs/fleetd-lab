fleetd's merge train takes a pull request that is ready to land, rebases its branch onto the current main, collects the tier reviews the change requires, waits for the ci check to pass on the rebased commit, and then merges it into main as a squash merge, the only merge method main allows. If the rebase conflicts, a required review is missing, or ci fails, the train does not merge the pull request. The train alone sets the fleetd/train commit status, which main requires alongside ci before any merge is allowed.
