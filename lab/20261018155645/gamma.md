fleetd's merge train takes a writer's pull request and lands it on main without anyone merging it by hand. It rebases the branch onto the current main, collects the tier reviews the change requires, and waits for the required ci check to pass before it does anything else. Once the rebase is clean, the reviews are in, and ci is green, the train squash-merges the change, which is the only merge style main allows. If the rebase hits a conflict, a review is withheld, or ci comes back red, the train does not merge; it sends the problem back to the writer so the branch can be fixed and resubmitted. The train is also the only actor that posts the fleetd/train commit status that main requires, so a writer never merges the pull request or marks it as passing on their own.
