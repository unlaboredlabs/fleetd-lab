fleetd's merge train is the only thing that merges pull requests into main in this repository. Writers push their task branches and open ready pull requests, then leave them alone; the train queues each enqueued pull request, runs its own review of the change, and waits for the ci check to go green on the exact tree that would land before it squash merges the queue in order and posts the fleetd/train status that main requires. When something stands in the way, such as a blocking review finding, a merge conflict or red CI, the train does not merge the pull request but sends it back to its writer to fix, so main only ever moves forward through the train.
