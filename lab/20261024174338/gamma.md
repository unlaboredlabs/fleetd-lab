fleetd's merge train is the only thing that merges pull requests into main in this repository. Writers push their task branch and open a ready pull request, and the train queues each enqueued pull request, runs its own review of the change, and waits for the ci check to go green on the exact tree that would land before it merges the queue in order. When something stands in the way, the train hands it back rather than forcing it through: blocking review findings, merge conflicts and red CI all go back to the writer to fix, so a writer never merges a pull request or posts the fleetd/train status by hand.
