fleetd's merge train is the only thing that merges pull requests into main in this repository. Writers push their task branch, open a ready pull request and leave it alone; the train queues each enqueued pull request, runs its own review of the change, and then waits for the ci check to pass on the exact tree that would land, so a green run on a stale base does not count. Once review and CI both hold, it squash merges the queued pull requests in order and posts the fleetd/train status that main requires. When something stands in the way, the train sends it back to the writer instead of merging: blocking review findings, merge conflicts with main and red CI all return to the writer to fix, and the pull request rejoins the queue after the fix is pushed.
