fleetd's merge train takes pull requests that are ready to land and merges them into main one at a time. For each queued pull request it rebases the branch onto the current main, waits for the required ci check to pass, and then merges it, using a squash merge as this repo requires. If the rebase hits a conflict or ci comes back red, the train does not merge the pull request; it reports the conflict or the failing run back to the writer so they can fix the branch and requeue it. The train is the only actor that sets the fleetd/train commit status, which main requires alongside ci before a merge is allowed.
