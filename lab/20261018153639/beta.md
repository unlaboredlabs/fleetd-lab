fleetd's merge train takes approved pull requests and lands them on the default branch one at a time. For each entry it rebases the branch onto the current main, waits for the required CI checks to finish on the rebased commit, and merges only when they pass. If the rebase hits a conflict, or CI goes red, the train does not merge; it sends the conflict or the failing check back to the writer so the branch can be fixed and re-queued.
