In fleetd, the merge train is the only path that merges pull requests into main in this testbed. It processes one change at a time: rebase onto the latest main, wait for ci, and squash-merge when ci is green, since main allows squash merges only. Conflicts and failing ci are never merged around; the train sends them back to the writer as a result to act on. The fleetd/train status it posts is one of the two checks main requires, so writers should not merge or set that status themselves.
