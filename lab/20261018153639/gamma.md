fleetd's merge train takes a writer's pull request and lands it on main without anyone merging it by hand. It rebases the branch onto the current main, waits for the required ci check to pass, and then squash-merges the change, which is the only merge style main allows. If the rebase hits a conflict, or the ci check comes back red, the train does not merge; it sends the conflict or the failing result back to the writer so the branch can be fixed and resubmitted. The train is the only actor that posts the fleetd/train commit status that main requires, so a writer never merges or marks the pull request as passing on its own.
